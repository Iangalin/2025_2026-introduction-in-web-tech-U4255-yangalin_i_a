# Правила вклада

Это персональный учебный репозиторий по дисциплине «Введение в веб-технологии» ИТМО.
Внешний вклад не предполагается, но если вы хотите указать на ошибку в моих отчётах, сделайте это так:

## Issue
- Заголовок начинайте с флага: `[BUG]`, `[QUESTION]`, `[PROPOSAL]`.
- Укажите, к какой лабораторной (`lab0/lab1/lab2/lab3/coursework`) относится замечание.
- Если это про код — приложите команду, которую запускали, и фактический вывод.

## Pull Request
- Одна логическая правка — один PR.
- Не правьте чужой текст в шапке отчёта (`University`, `Faculty`, `Author`, `Date of finished`) — это персональные поля.
- Сохраняйте стиль Markdown, существующий в файле (русский язык в прозе, английские термины — без перевода).

## Workflow веток
- `main` — защищённая, только через PR.
- `develop` — основная рабочая ветка.
- Тематические ветки: `lab<N>/<краткое-описание>`, например `lab2/github-actions-secrets`.

## Code review
- Любое изменение в `main` идёт **только через Pull Request** из `develop` или тематической ветки.
- Перед мержем PR должен быть прочитан владельцем репозитория: проверяется соответствие требованиям лабораторной из `docs/lab<N>-spec.md`, отсутствие секретов в diff и осмысленные сообщения коммитов.
- Замечания фиксируются в комментариях PR; автор правит код в той же ветке, **не пересоздавая PR**.
- Мерж выполняется кнопкой *Merge pull request* → *Confirm merge* (в этом учебном репозитории — без squash, чтобы сохранить историю шагов лабораторной).
- После мержа тематическая ветка удаляется и локально (`git branch -d`), и на remote (`git push origin --delete`).

## Коммиты
Короткие, императивные, на русском или английском. Один логический шаг — один коммит.
Префиксы по желанию: `lab0:`, `lab1:`, `docs:`, `chore:`.
